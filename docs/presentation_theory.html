Motivation & Bottleneck Analysis

Problem: Transformer Attention is Expensive on FPGA

Transformer models provide strong language understanding, but their attention mechanism contains hardware-expensive operations.

Why Softmax is expensive

  • •
    Exponential calculation
    Non-linear exponential ex requires heavy floating-point logic or large lookup tables
  • •
    Accumulation
    Row-wise summation of dynamic range exponentials
  • •
    Division / normalization
    Iterative restoring divider adds multi-cycle latency
  • •
    Fixed-point scaling and requantization
    Requires conversion stages between INT8 and real fixed-point scales

Stage 1: Input Ingestion

From Sentence to Embeddings

Input Sentence: “Turn on the lights.”

1. Tokenization

The sentence is split into individual tokens:

Turn → on → the → lights

For illustration, we assign token IDs:

[3] [7] [2] [12]
Vocabulary mapping is static and stored in on-chip ROM.

2. Embedding Lookup

Each token ID is mapped to a learned numerical vector using an embedding table.

Turn (ID 3) → [e1, e2, e3, ... , e32]
On (ID 7) → [e1, e2, e3, ... , e32]
The (ID 2) → [e1, e2, e3, ... , e32]
Lights (ID 12) → [e1, e2, e3, ... , e32]
Produces INT8 dense matrix X (8 tokens × 32 dimensions).
Stage 2: Linear Projections

From Embeddings to Q, K and V

Input Transformation

The embedding matrix X is transformed into three representations:

Query (Q)
“What information am I looking for?”
Key (K)
“What information does each token represent?”
Value (V)
“What information should actually be passed forward?”
Linear Projection Equations
Q = X · WQ
K = X · WK
V = X · WV
X = input embedding matrix
WQ, WK, WV = learned weight matrices

Stage 4: Normalization Step-by-Step

Softmax

Softmax(xi) = exi ∑j exj
Why do we need Softmax?

Softmax converts arbitrary scores into normalized weights:

  • • Each weight is positive
  • • Larger scores receive larger weights
  • • The weights sum approximately to 1
Raw score vector: [5, 2, 1, 3]
1. For numerical stability, find maximum:
m = max(x) = 5
2. Subtract the maximum:
z = x − m = [0, −3, −4, −2]
3. Compute exponentials:
ez ≈ [1, 0.0498, 0.0183, 0.1353]
4. Sum:
∑ ez ≈ 1.2034
Therefore:
Softmax(x) ≈ [0.8306, 0.0414, 0.0152, 0.1124]
Core Innovation

Our Approach: Integer-Native Softmax

Our key mathematical transformation:
ez = 2z · log2(e)
Since:
log2(e) ≈ 1.442695
we approximate it using:
log2(e) ≈ 2316 = 1.4375
Therefore:
ez ≈ 223(z) / 16
Division by 16 is a 4-bit wire slice • No hardware multipliers or dividers needed for base conversion!
Hardware Realization

Binary Shift Exponentiation

Replacing Expensive Exponential ROMs with Pure Hardware Bit-Shifts & 16-Word Refinement

Powers of Two in Hardware

Digital FPGAs natively compute powers of two using single-cycle barrel shifters:

23 = 8,   24 = 16,   2−4 = 116 = 0.0625
• Integer Component: Bit-slice [7:4] drives an 8-bit barrel right-shifter.
• Fractional Component: Bit-slice [3:0] indexes a tiny 16-entry correction LUT for 2−f/16.
• Tier 0 uses shift-only (0 ROM). Tier 1 adds 16 words for 410x higher precision.
